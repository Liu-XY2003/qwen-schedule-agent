# v0.1.0 — 首次发布

中文一句话 → 结构化工具调用 → 可视化日历。**全部在本机推理，不调用任何 API。**

```
"下下周二上午九点加一门计算机原理，在教三201"
        ↓  Qwen3-0.6B + LoRA ── llama.cpp 约束解码
{"module":"class","action":"add","title":"计算机原理",
 "when":{"date_kind":"weekday","date_value":"TU","week_offset":2,
         "time":"09:00","period":"am"},"location":"教三201"}
        ↓  Pydantic 契约校验 → resolve_time() 确定性推导
2026-10-06 09:00  计算机原理（教三201）
```

## 30 秒跑起来

```bash
# 1. 推理后端（从 llama.cpp releases 下对应平台的构建，只要 llama-server）
llama-server -m qwen3-0.6b-sched-v4-Q4_K_M.gguf \
             -ngl 99 -c 2048 --host 127.0.0.1 --port 18080 --jinja -np 1

# 2. 应用
pip install -r bridge/requirements.txt
SCHED_LLAMA_URL=http://127.0.0.1:18080 \
  uvicorn app:app --app-dir bridge --host 127.0.0.1 --port 8800
```

打开 <http://127.0.0.1:8800>。

- `-ngl 99` 把层全丢给 GPU/核显；纯 CPU 用 `-ngl 0`
- `--jinja` **必须加**，否则服务端不会按 chat template 解析，输出会不对

手机端见 [AI-ScheduleAssistant](https://github.com/Liu-XY2003/AI-ScheduleAssistant)。

## 这一版有什么

- **约束解码**：JSON Schema 编译成解码约束，枚举外的值结构上不可能出现（无约束时会漏出 `fuzzy:"before"` 这类值），速度几乎无损
- **模型不算日期**：只输出 `week_offset: 2` 这样的相对表达，绝对日期由确定性代码推导，可单元测试
- **一份 Schema 五处使用**：训练标签 / 解码 grammar / MCP inputSchema / Pydantic 校验 / 验收断言同源，CI 断言零漂移
- **反向构造训练数据**：先采样结构化记录再渲染成中文，标签由构造保证正确
- **两套主题**：纸感 / 夜航，网页与安卓共用一份 token
- **可选访问令牌**：`SCHED_TOKEN`，防止把无鉴权的服务暴露到网上

## 已知限制

- `action` 目前只有 `add`，改 / 删只能在界面上手点
- 没有提醒推送
- 拒答（reject / clarify）的负样本偏少，是弱项
- 单人应用：一个后端服务一个人。多人共用需要自己加数据隔离
