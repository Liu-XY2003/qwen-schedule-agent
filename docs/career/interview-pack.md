# 面试准备包 · 基于 LoRA 微调后的 Qwen3 模型的 AI 日程助手

> 一、二部分念到能自然说出来；三部分快速过；四部分只在卡壳时用。
> 原则：**不会就说不确定，但把边界说清楚**——比硬编更有说服力。

## 一、项目介绍（口述稿，约 2 分钟）

本项目是一个**本地优先的 AI 日程助手**，核心是基于 **LoRA 微调的 Qwen3 小模型（0.6B–4B）**
构建的「自然语言 → 结构化工具调用」转换层。

产品能力分两个层次。**指令级**：用户以自然语言描述单条日程（如"下周二上午九点加一门
计算机原理在教三201"），系统经约束解码输出结构化命令并落库。**规划级**：用户提供一段
非结构化的待办素材，系统先抽取任务与约束，再交由约束求解器生成一周可行计划。

技术上有三个关键取舍。第一，**模型只承担语义归一化，不承担任何计算**——契约层只允许
相对时间表达，绝对时间的解析下移到确定性代码，从而消除"模型算术错误"这一整类不可测缺陷。
第二，**规划能力交给确定性求解器而非语言模型**——CP-SAT 求解耗时仅 20–30ms，且在不可行时
能定位到具体冲突约束，这既是准确率问题也是可解释性问题。第三，**以单一 JSON Schema 作为
唯一事实源**，同时派生约束解码文法、LoRA 训练标签、执行层校验与 MCP 工具描述，
并以 CI 断言防止契约漂移。

实测在无独立显卡的核显设备上，端到端中位延迟 **641ms**，结构合规率 **4372/4372**。

## 二、模拟 Q&A

### 2.1 基础部分

**Q：这个项目解决什么问题？**
A：把自然语言可靠地转换为工具调用。难点不在语义理解，而在**输出必须结构合法、语义正确**。
做法是**分离不确定性**：语言理解交给模型，时间解析与排期交给确定性代码。

**Q：为什么不用云端大模型？**
A：**隐私**（日程属高敏感个人数据，不宜出本机）、**成本**（高频轻量调用不经济）、
**可用性**（离线可用）。代价是模型能力受限，因此需要约束解码、规则层等手段补齐工程可靠性。

**Q：为什么选择 LoRA 微调，而不是直接用更大的基座模型？**
A：实测过基座模型在当前契约下的表现：1.7B/4B 零样本准确率仅 14%/19%，
**换更大的模型并不能解决"不会用新契约"的问题**。LoRA 只需训练低秩旁路矩阵，
显存与成本低一两个数量级，且能让模型学到训练分布里的**联合约束**
（多条待办、时长与截止的对应关系），这是 few-shot 补不上的。

**Q：什么是约束解码？**
A：将 JSON Schema 编译为**文法（GBNF）**，推理时每个 token 只能在文法允许的候选集内采样，
使输出在结构上不可能非法。但需注意它**只保证格式，不保证语义**。

**Q：为什么坚持"模型不算日期"？**
A：模型做算术产生的是**不可测错误**——日期偏移一周在界面上不可见，用户不会报错，
只会事后发现。将日期解析下移到确定性代码后，该类缺陷消失且可被单元测试覆盖。

**Q：MCP 在项目中扮演什么角色？**
A：MCP 定义的是**工具的暴露与调用协议**，而非"自然语言转 JSON"那一层，两者常被混淆。
项目中 MCP 工具定义（`inputSchema`）与解码文法、训练标签同源派生，因此任意 MCP 客户端
可零适配接入，且不会与模型侧契约产生分歧。

**Q：CP-SAT 在项目中承担什么职责？**
A：求解带约束的排期问题：输入任务（时长/截止/优先级）与可用性限制，输出满足全部硬约束、
软约束代价最小的周计划。作为确定性求解器，其结果是可复现、可解释的。

### 2.2 技术深入部分

**Q：约束解码的代价？"保证格式不保证语义"具体指什么？**
A：两个代价：**首 token 延迟**（语法需预编译）与**表达受限**（Schema 未定义的字段无法生成，
因此契约设计本身即产品设计）。语义层面，它能保证 `module` 落在枚举内，但无法判断
"开会"应归入 `meeting` 还是 `class`。所以执行层保留了 `clarify`（追问）与 `reject`（拒答）
两个出口，避免模型强行输出一个形式合法但语义错误的答案。

**Q：4B 为什么反而表现更差？**
A：Qwen3 默认开启 thinking，4B 将 token 预算大量消耗于推理链——实测 298 个 reasoning chunk、
**正文零输出**。`--reasoning-budget 0` **无效**：它仅将文本迁移到 `content` 字段，推理行为未变，
且产生了错误的年份。真正生效的是 `--reasoning off`，关闭后输出**逐字一致**，延迟 1900ms → 641ms。

**Q："一份 Schema 四处消费"如何防止契约漂移？**
A：四处消费路径不同但来源唯一：约束解码由 Schema 生成 GBNF；训练集生成器据其决定标签字段；
执行层用 Pydantic 镜像做校验；MCP 服务端以 `Literal[*SCHEMA_ENUM]` 直接取枚举。
CI 设两条断言：Pydantic 镜像字段集合等于 Schema；MCP 工具枚举等于 Schema 枚举。
"训练时一个字段、调用时另一个字段"这类静默失效，在提交前即被拦截。

**Q：反向构造如何保证标签正确？又如何证明校验器有效？**
A：采用**先有标签、再渲染文本**的顺序，标签由真值直接生成，构造上不可能出错。但渲染可能遗漏
（文本未说时长、标签却写 120 分钟），模型便会学到臆测。因此另写校验器逐条断言
"标签每个字段均可由文本推断"，且**按分句**检查——全文检查会被其他事项的措辞掩盖。
更关键的是为校验器写自测：注入五类错误标签，断言全部被捕获、且干净数据零误报。
**一个永远通过的校验器等价于没有校验器**——初版即踩过此坑：把 `priority` 改为 `high`，
但样本本已为 `high`，等于未做修改。

**Q：规则层与模型的分工边界如何划定？会不会破坏模型的正确输出？**
A：判据是"**规则可做且更可靠的，就不交给模型**"。模型抽取 `keep_free`（禁排时段）仅 30.6%，
而"周三上午别排东西"这类句式正则几乎不会出错，接管后升至 94.4%。
曾两次引入错误：将约束中的"周三"误作事项截止日 → 改为**先抽约束、记录字符区间、抹除后
再为事项匹配日期**；标题与文本不完全匹配时退化为全文查找 → 改为**定位失败即不修改**。

**Q：当前 39% 如何提升到 80%？**
A：短期靠微调，数据集与训练套件已就绪（4000 条反向构造、标签 100% 校验通过），仅缺算力。
长期靠**联合分布**：基座逐 token 贪心，缺乏"整条样本自洽"的约束，导致单字段正确但整体不齐。
此外将实现 `plan_diff` 增量重排——相比整周重排，容错性与稳定性更好。

## 三、技术知识点扫盲

### 3.1 基础

| 概念 | 一句话 |
|---|---|
| **LoRA** | 冻结原模型，只训练低秩旁路矩阵（秩 r 通常 16），显存与成本降一两个数量级 |
| **GGUF / 量化** | llama.cpp 的模型格式；Q4_K_M 为 4bit 混合量化，体积约为 fp16 的 1/4 |
| **约束解码 / GBNF** | 按文法限制 token 候选集使输出结构合法；GBNF 是 llama.cpp 的文法语言 |
| **CP-SAT / NoOverlap** | 约束规划求解器，擅长排期；NoOverlap 约束一组区间互不重叠 |
| **MCP** | 工具与上下文暴露的标准协议，负责"描述、发现、调用" |

### 3.2 技术深入

| 概念 | 要点 |
|---|---|
| **thinking mode** | Qwen3 默认先生成推理链；`--reasoning-budget 0` **不能**关闭，须 `--reasoning off` |
| **首 token 延迟 vs 总时长** | 约束解码拉高首字延迟（语法编译），总时长可能更短；评测需分开看 |
| **bf16 vs fp16** | 原生 bf16 需 sm_80+；`torch.cuda.is_bf16_supported()` 在 sm_75 上**误报 True** |
| **逐 token 贪心 vs 联合自洽** | 单字段准确率相乘会急剧衰减，是"每字段都对、整条不对"的根因 |
| **Wilson 置信区间** | 小样本下比正态近似可靠；21 条样本的 95% CI 达 ±11pp，不足以支撑结论 |
| **契约漂移** | 多处手写同一结构导致逐渐不一致；解法是单一事实源 + CI 断言 |

## 四、答不上来时的应对话术

> 目标不是糊弄，而是**展示你知道边界在哪、以及会怎么查**。

1. **完全没听过** → "这块我没有深入了解，不敢妄断。我理解它面向 X 类问题，但机制不确定。
   如果工作中要用到，我会先查官方文档与最小可运行示例，再回来确认。"
2. **记得结论忘了推导** → "结论我记得是 X，但推导需要重新走一遍。当时是实验得出的，
   我可以把测量方法讲一下——你更关心结论还是方法？"
3. **被追问到盲区** → "这一点我确实没有考虑到。初步判断影响可能在 A 与 B 两方面，但需要验证。
   您能指一下是哪个方向吗？我想顺着补一下。"（**把追问变成学习机会**）
4. **数据记不准** → "具体数值我不保证，量级是 600 多毫秒，准确值在仓库 benchmark 文档里。
   我更确定的是**相对关系**：关闭 thinking 后快了约 3.6 倍，输出逐字一致。"
5. **被指出方案有问题** → "您说得对，这确实是漏洞。当时我在 X 与 Y 之间选择了 X，原因是……。
   若按您的方案改，我担心会引入 Z。您认为 Z 可以接受吗？"（**承认取舍，不硬辩**）
6. **通用兜底** → "整体我还不确定，但有一点可以确定：______。其余我想确认后再答。"
