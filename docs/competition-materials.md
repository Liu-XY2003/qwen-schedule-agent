# 参赛材料准备清单（第二十届全国大学生软件创新大赛）

> 基于 2026-11 的调研整理。**具体表单项与截止日期以本校校赛通知和组委会官方通知为准**
> —— 本文是"该准备什么"的框架，不是官方要求。

---

## 零、先去确认三件事（本周）

1. **本校校赛通知** —— 教务处 / 软件学院 / 校团委官网。历史节奏：12 月上旬截止报名，
   12 月中下旬校赛答辩。**错过要等一年。**
2. **组队** —— 规则允许跨校跨专业，团队 ≤6 人（队长 1 + 队员 ≤3 + 指导老师 ≤2）。
   个人项目建议补 1–2 人：一个负责文档/演示，一个负责 UI/视频。
3. **一稿多投冲突** —— 校赛通常要求"原创且未参加过其他公开比赛"。
   若同时想报挑战杯，**必须发邮件问组委会并留证据**。

## 一、核心材料（必须自己写，占分最重）

### 1. 作品文档 / 技术报告

建议结构（按评审关注点排，不按开发顺序）：

| 章节 | 写什么 | 为什么重要 |
|---|---|---|
| **1. 问题与定位** | 一句话说清是什么；不是"又一个日历 App" | 评审看几十份，前 30 秒决定印象 |
| **2. 现有方案的不足** | 云端 AI 日程工具是黑盒、贵、数据外流 | 建立"为什么需要你" |
| **3. 技术方案** | 三层架构：理解(LLM) / 求解(CP-SAT) / 表达 | 这是最有说服力的部分 |
| **4. 关键设计决策** | 模型不算日期、一份 Schema 五处用、约束解码 | 展示工程判断力，不是堆功能 |
| **5. 实测数据** | 641ms 端到端、20/20 验收、4372 条数据 0 失败 | **有数字的方案比有想法的方案可信** |
| **6. 创新点** | 见下方 §二 | 评审会照着评分表找 |
| **7. 局限与后续** | 主动说清楚不足 | 显得诚实、有判断 |

**写作要点：**
- 每个技术选择都配"为什么"，而不是"是什么"
- 每个结论都配数字（延迟、通过率、体积）
- 用对比表格代替段落（评审时间有限）

### 2. 创新点提炼（按评分表倒推）

调研到的赛题方向是"AI 赋能真实生活场景 / 端侧 AI / 智能体"。对应地：

| 创新点 | 一句话表述 | 支撑证据 |
|---|---|---|
| **架构创新** | 规划交给确定性求解器，模型只做语义翻译 | 引用 NATURAL PLAN：GPT-4 规划成功率仅 31% |
| **端侧可行** | 0.6B 模型在核显上 641ms，无需联网、无需显卡 | 实测表格 |
| **可解释** | 每个安排都能说出为什么（约束直接生成的理由） | 界面截图 + 求解器冲突集 |
| **工程方法论** | 一份 Schema 派生训练标签/解码约束/校验/验收 | CI 断言零漂移 |
| **数据自造** | 反向构造法，标签由构造保证正确 | 4372 条 100% 合规 + failed=0 |

> **建议主打第 1 条和第 4 条。** 前者是"想法新"，后者是"做得扎实"，两个维度都占分。

### 3. 软件著作权 / 作品原创性声明

- 按校赛要求提交原创声明
- 如已申请软著，附证书（个人可申请，官方登记免费，周期约 30–60 工作日）
- **开源与原创的关系要说清楚**：用了哪些开源组件（Qwen3/llama.cpp/FastAPI/Compose）、
  哪些是自己写的。赛事普遍要求标注开源比例。

## 四、匿名评审的特殊处理 ⚠️

赛事要求材料里**不得出现校名、姓名、指导老师、学院、专业、班级**。
但你的项目在 GitHub 上是公开的，仓库和账号是关联的。三条路：

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A. 提交源码包，不附仓库链接** | 用 `git archive` 导出 zip，去掉 .git | 最稳，但评审看不到提交历史 |
| **B. 附仓库链接，接受可识别** | 很多赛事只审"文档匿名"，代码仓库不算材料 | 有风险，**必须先问组委会** |
| **C. 建一个匿名镜像账号** | 新 GitHub 账号放一份，文档里只留镜像链接 | 干净，但要维护两份 |

**建议：先发邮件问组委会"匿名评审是否覆盖开源仓库链接"，按回复决定。**
这个问题很常见，组委会一般会有明确口径。

另外要清理的：
- [x] 脚本里的本机用户名（已改成 `$env:USERPROFILE`）
- [x] 截图里的真实 IP（已重拍）
- [x] 示例数据里像凭据的内容（已换）
- [x] git 提交者是 noreply 邮箱（安全）
- [ ] PPT/文档里如果有人名水印、个人主页链接，去掉

## 六、容易被忽略的扣分项

1. **文档里出现校名/姓名** → 直接判违规，成果再好也没用
2. **只讲功能不讲原理** → 评审看不出技术含量
3. **没有实测数据** → "很快"不如"641ms"
4. **演示视频里翻车** → 一定要预录，不要现场跑
5. **开源比例没说明** → 用了 Qwen3/llama.cpp 要标注清楚，藏着反而扣分
6. **README 只有中文** → 国际评委/企业评委可能看英文
7. **代码跑不起来** → 加个 `demo.sh` 的成本很低，收益很高
